## Base-path evidence (exact)
- vite.config.ts:9 `const basePath = '/texlyre/';` and :14 `base: basePath`. It is a literal, and there is no env var for it (the only env reads are VITE_USE_HTTPS and npm_package_version, lines 7 and 10).
- texlyre.config.ts:8 `baseUrl: '/texlyre/'`. The supported way to change it is to edit that file and run `generate:configs`, which regex-rewrites vite.config.ts (scripts/generate-configs.ts:182-183, 383). That is a source edit plus a script outside the build Anybuild runs.
- public/sw.js:4 `const BASE_PATH = '/texlyre/';` (generated by scripts/update-sw-version.js:33-51, run only in build:prod/build:local). The service worker app shell is `BASE_PATH + 'index.html'` (sw.js:32).
- Consequence at a domain root: built HTML would reference `/texlyre/assets/...` while sws serves the files at `/assets/...`, so the JS, CSS, WASM and worker assets would 404. The service worker would also scope to `/texlyre/`.
- `vite build --base=/` would override the base, but Anybuild runs `pnpm run build` with no arguments, and that would still leave sw.js and `__BASE_PATH__` wrong. There is no minimal supported fix without changing repo config, and that change would also break the upstream GitHub Pages deployment at `/texlyre/`.
