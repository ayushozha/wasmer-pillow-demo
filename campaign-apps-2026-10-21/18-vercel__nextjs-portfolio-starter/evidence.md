Generated commands: install `yarn install`, prune `yarn workspaces focus --all --production` (`resources/starlib/tools/node.bzl:21-33`), build `yarn dlx next-bundle@1.0.0 --build-command 'yarn run build'` (`node.rs:94-101`, `458-471`, `1646-1668`), start `node .next-bundle/server.mjs` (`node.rs:473-475`).
- Reproduced locally with Node 24.22.1 + Yarn 4.18.1 (current `latest` of `@yarnpkg/cli-dist`, standing in for the unpinned builder yarn) on a clean copy: `yarn install` migrates the v1 lockfile and writes `.yarnrc.yml` with `nodeLinker: node-modules` - exit 0. Then the generated build command **fails**: `Error: The target project does not declare a next dependency.` (exit 1). Cause: next-bundle@1.0.0 `bin/build.mjs:54-57` resolves the project from `process.env.INIT_CWD || process.cwd()`, and under Yarn Berry `yarn dlx` that is the temporary dlx project. Passing the absolute project path (`yarn dlx next-bundle@1.0.0 "$PWD" --build-command 'yarn run build'`, not what Anybuild generates) builds fine; then prune exit 0 and `node .next-bundle/server.mjs` on 3312 serves `/` 200, `/posts/markdown` 200 + `<h1>Markdown Examples`, `/feed.xml` 200 (2 items, but `application/octet-stream` instead of `application/xml`), unknown 404.
- With Yarn 1 instead, `yarn dlx` does not exist, so the generated build command would fail as well. Either way, on Anybuild v0.33.0 a Yarn project with Next.js should not build zero-config. Not tested: whether `ANYBUILD_NODE_PACKAGE_MANAGER=npm` (no `package-lock.json`, so unpinned resolution) works; that would not be a one-click path anyway.
