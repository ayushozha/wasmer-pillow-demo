Title: Add a "Hosting your own copy" section with a Wasmer Edge option

<a href="https://wasmer.io/apps/create?github=johnnesky%2Fbeepbox"><img src="https://img.shields.io/badge/Deploy%20to-Wasmer-171717?style=for-the-badge&amp;logo=wasmer&amp;logoColor=white&amp;labelColor=171717" alt="Deploy to Wasmer" height="48"></a>

I work at Wasmer. Wasmer Edge is a cloud hosting platform powered by WebAssembly; it can host this repository’s generated static site. References: [Wasmer Edge docs](https://docs.wasmer.io/edge/), [Git deployments](https://docs.wasmer.io/edge/git/).

This change was prepared with AI assistance (Anthropic's Claude); the testing described below was run locally, and I did not deploy it to Wasmer.

## Summary

This adds a short "Hosting your own copy" section to the README with a Deploy to Wasmer badge, plus a small root `Anybuild` file that only Wasmer's builder reads.

- `README.md`: the new section sits right after the paragraph about the `website/` folder. It says that after `npm run build` the `website/` folder is a static site, and gives fork-first guidance: fork, then import your fork, because importing johnnesky/beepbox directly does not copy it into your account. It also says what the `Anybuild` file does, and to select node-static if the import page shows a different preset.
- `Anybuild`: generated by `anybuild generate . --provider node-static` (Anybuild 0.33.1), with two edited lines:
  - `static_dir = "website"` instead of the generator's default `"dist"`;
  - the app name set to `beepbox` (the generator had used my local directory name).

  All other lines are generator output unchanged: npm, `npm_version = "11"`, Node 24.

No app code, dependencies, `package-lock.json`, scripts or `website/app.yaml` change.

## Why this repository

The README already describes building your own copy and where the result lives:

- "Then to build this project, open the command line and run: ... `npm install` / `npm run build`" (README "Compiling").
- "After compiling the editor code, open website/index.html to see the editor interface."
- "The player/ folder has a miniature song player interface for embedding on other sites."
- "The website/ folder contains index.html files to view the interfaces. The build process outputs JavaScript files into this folder."

This section gives someone with their own fork a way to serve the built `website/` folder (editor, embeddable player and synth example) from that fork. It does not change anything for beepbox.co.

The `Anybuild` file is needed here. Without it, Wasmer's builder detects a plain Node project with `npm run build` but no output directory and no start command, so it has nothing to serve. A `Staticfile` pointing at `website/` would serve the folder without running the build, and the gitignored `beepbox_editor.min.js` and `player/beepbox_player.min.js` would then be missing. The declared node-static config runs `npm install` and `npm run build`, then serves `website/`.

## Testing

All tests ran locally against base commit `355e510099d230d066d95074c16d748d59fe054c` plus this patch. I did not deploy to Wasmer.

- **Normal build:** Node 24.22.1, npm 11.19.1. `npm ci` and `npm run build` passed.
- **Builder plan (Anybuild 0.33.1):**
  - Base commit: provider node, `npm install` then `npm run build`, with no output directory and no start command.
  - Patched commit: "Using static Node.js provider declared in Anybuild", provider node-static, `static_dir` website, npm 11.
  - I also rendered the Docker build for the patched commit without building it, using a stub `docker` client. It runs `mise use --global "node@24"` and `mise use --global "npm@11"`, copies `package-lock.json` before `npm install`, runs `npm run build`, and copies `website/` to the served directory.
- **Builder-step replay:** I re-ran the planned install and build steps locally with Node 24.22.1 and npm 11.19.1. Both passed. `package-lock.json` was byte-identical after install, `npm ls --all` passed, and all 237 installed package versions matched the lockfile.
- **Static serving:** I served the replay output with native static-web-server 2.32.2 (the version Wasmer runs as WebAssembly) and 2.38.0. I did not test Wasmer's WebAssembly build itself.
  - 200: `/`, `/player/`, `/beepbox_editor.min.js` and its source map, `/player/beepbox_player.min.js`, `/beepbox_synth.min.js`, `/synth_example.html`, `/2_3/`, `/3_0/`, `/3_0/player/`, `/beepbox_offline.html`, `/manifest.webmanifest`, `/service_worker.js`, and icons.
  - `/player` redirects (308) to `/player/`. A missing path returns 404.
- **Headless Chromium**, on both server versions:
  - The editor at `/` renders. Pressing Play creates an AudioContext that reaches the running state, and the Pause button appears.
  - `/player/` with a song hash copied from the editor plays, with a running AudioContext.
  - `/synth_example.html` loads the synth.
  - There were no console errors and no failed local requests on these pages.

## Limitations

- I did not deploy this to Wasmer. The badge opens Wasmer's import page for this public repository. It does not fork or copy the repository; to customize the site or get rebuilds on push, import your own fork.
- If the import page shows a different preset, select node-static (static Node build). I can't promise the live import picks up the declared `Anybuild` automatically.
- The build needs network access to the npm registry.
- `website/app.yaml` settings don't apply on Wasmer: the canonical `Link` header, the HTTPS redirect and the `Content-Disposition` header for `beepbox_offline.html`. The offline link in `index.html` already uses the `download` attribute. `app.yaml` itself would be served as a plain file.
- The service worker has scope `/`, so a copy should be served at a domain root. Its install step also precaches lamejs from cdn.jsdelivr.net. My sandbox blocks that host, so I did not see the service worker activate; all of its same-site precache entries returned 200.
- The pages still load Roboto from fonts.googleapis.com, and lamejs from cdn.jsdelivr.net for .mp3 export. The legacy `/3_0/` page also loads platform.twitter.com, which my sandbox blocked (an external request, not a missing local file).
