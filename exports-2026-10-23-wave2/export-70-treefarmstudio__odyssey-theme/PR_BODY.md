## Summary

Adds a Deploy to Wasmer badge to the README's "Deploy" section, after the link to Astro's deploy guide. This is a two-line README change with no code or config changes.

Disclosure: I work at Wasmer. I prepared this change with help from Claude, an AI assistant, and reviewed and tested it before opening this PR.

The button opens Wasmer's import page for this public repository, where you review the detected build settings and click Deploy; it does not create a copy of the repository in your GitHub account. To customize the site and redeploy on changes, fork the repository and import your fork instead.

## Why this repo

The README already invites people to host the theme on their favorite static host. Wasmer's builder detects Odyssey as a static Astro site, runs `npm install` and `npm run build`, and serves `dist/`, so the theme deploys as-is.

## Testing

All on `d191e5715a2519e25be4629b933189c421b30a1a` (current `main`) with this change applied, as a local replay of the plan generated by Wasmer's builder (Anybuild v0.33.0):

- Detected: static Node.js provider, framework Astro, npm 11, output directory `dist`.
- `npm install` (Node 24.22.1, npm 11.21.1, with only `package.json` and `package-lock.json` staged first, as the builder does): exit 0.
- `npm run build`: exit 0; 18 pages and 76 files in the output.
- `dist/` served with a local native static-web-server 2.38.0 (the version Anybuild's plan pins; Wasmer's hosted runtime uses its own WASI static-web-server package, which was not tested here).
- `curl` results: `/`, `/blog/`, a blog post, a tag page, three theme pages, `/company/about/`, `/company/contact/`, `/landing-pages/landing-1/`, `/sitemap.xml` and `/404.html` returned 200. Missing paths returned 404 with the theme's own `404.html` page.
- All 60 same-origin URLs referenced from the 18 built HTML pages and 2 CSS files resolve: 45 returned 200 directly, and the 15 internal links written without a trailing slash (for example `/blog`) returned a 308 redirect to the slash form, which then returned 200.

## Limitations

- No deployment was made. The Wasmer import page and the badge image were not opened from the test environment.
- The contact and newsletter forms `POST` to `/contact-thank-you` and `/newsletter-thank-you`. A static host cannot handle these (the local server answered 405), so, as on any static host other than one with built-in form handling, the forms need an external endpoint such as Formspree or Formspark.
- `astro.config.mjs` sets `site` to the theme's demo domain, so canonical and sitemap URLs point there until a deployer changes it. The build writes `sitemap.xml` (there is no RSS feed).
- The built pages load no third-party scripts or analytics (`BaseHead.astro` has only an empty Google Analytics placeholder comment). Fonts are served from the site itself.
- The repository's `Deploy` workflow runs on pull requests and uploads to Deno Deploy; it may not be able to authenticate from a fork PR. A failure there would not be caused by this README change.
- The repository has had little recent maintainer activity (last commit on `main`: 2024-09-24), so I understand if this is not reviewed soon.
