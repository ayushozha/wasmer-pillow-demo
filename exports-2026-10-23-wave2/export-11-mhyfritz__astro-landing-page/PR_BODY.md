## Summary

Adds a short "Deploy" section with a Deploy to Wasmer badge to the README, between "Commands" and "Credits". This is a four-line README change with no code or config changes.

Disclosure: I work at Wasmer. I prepared this change with help from Claude, an AI assistant, and reviewed and tested it before opening this PR.

The button opens Wasmer's import page for this public repository, where you review the detected build settings and click Deploy; it does not create a copy of the repository in your GitHub account. To customize the site and redeploy on changes, fork the repository and import your fork instead.

## Why this repo

This is a landing-page template, so most people who use it want their own copy online quickly. Wasmer's builder detects it as a static Astro site, runs the `npm install` and `npm run build` listed in the Commands table, and serves `dist/`, so the template deploys without changes.

## Testing

All on `987617a50863d31bb865ee531391a191d74a878a` (current `main`) with this change applied, as a local replay of the plan generated by Wasmer's builder (Anybuild v0.33.0):

- Detected: static Node.js provider, framework Astro, npm 11, output directory `dist`.
- `npm install` (Node 24.22.1, npm 11.21.1, with only `package.json` and `package-lock.json` staged first, as the builder does): exit 0.
- `npm run build`: exit 0; 1 page and 37 files in the output.
- `dist/` served with a local native static-web-server 2.38.0 (the version Anybuild's plan pins; Wasmer's hosted runtime uses its own WASI static-web-server package, which was not tested here).
- `curl` results: `/` and `/index.html` returned 200. All 35 same-origin URLs referenced from the built HTML and CSS (the script, stylesheet, 7 Inter font files, 25 optimized images and the favicon) returned 200 with the expected content types. `/nope`, `/missing/` and `/missing.html` returned 404.

## Limitations

- No deployment was made. The Wasmer import page and the badge image were not opened from the test environment.
- `astro.config.mjs` sets `site` to the Netlify demo, so `og:url` and `og:image` point there until a deployer changes it, as on any host.
- The built page loads no third-party scripts or analytics. Fonts are bundled from `@fontsource-variable/inter`, so nothing is fetched from font CDNs. It is a single page, so there are no client-side routes to deep-link, and there is no custom 404 page.
- The repository has had little recent maintainer activity (last commit on `main`: 2024-11-24), so I understand if this is not reviewed soon.
